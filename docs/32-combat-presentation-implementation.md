# 双 Demo 战斗表现实施策划（2026-09-23）

## 目标与边界

保留瓦 Demo、新 Demo 各自的玩法、卡牌内容和数值。共享 3D 战斗角色与动作接口；两版都呈现“选牌→牌离手→角色出手／布防→效果命中→牌入弃牌或消耗堆”的因果顺序。玩家结束回合时，剩余手牌逐张弃掉，敌人有可辨认的出手阶段，下一回合手牌逐张从牌堆抽入。所有动画只是已有引擎结算的表现层，不能改伤害、抽牌顺序或随机数。

## 美术方向

角色为偏卡通的立体战术小队，避免写实人脸、现役选手肖像、Valorant 官方特工或皮肤的直接复刻。己方：较轻的青蓝战术服、可见脸部、发型和轻装备，姿态前倾。敌方：深色装甲、全脸遮挡、较厚肩甲和重武器，轮廓与己方一眼可分。敌人至少有三种可见轮廓变体，基于关卡敌人 ID 稳定选择；同一个敌人刷新后不变。避免仅换色，头部、肩部或武器轮廓必须变。两队保持现有舞台大小，不挤压卡牌区域；正面朝向应让玩家看得出动作。角色常态有轻微呼吸／持枪晃动。

本地实拍发现现有三人是同一套小人几何体的蓝色版与红色版，占据舞台上方一条窄带；头盔、衣身、手臂、武器剪影近乎一致。返修必须解决这个具体问题：敌方不使用己方小人的同一模板，至少 7 类对手（普通五类、强敌、Boss）按真实 enemy ID 确定性选型。基础进攻为轻突击三角阵，信息压制为天线／面罩技术兵，多段突击为双持快攻，防守反击为持盾重装，纪律控制为整齐警戒队列，强敌为外骨骼突击手，Boss 为高大指挥官。差别需要在黑色剪影下仍然辨认，且模型占舞台高度的大部分；不要只添加一个很小的头饰。不同幕可以给同一类增加肩甲／装备层级，但不能随机关卡 ID 映射成错误职业。己方三个队员也应有发型、装备、衣装层次的差异。画面可采用 2 位侧翼较小、1 位队长靠前较大的纵深构图，保留双方舞台同等占位。

## 动作与时间线

| 情形 | 表现顺序 | 验收 |
| --- | --- | --- |
| 攻击牌 | 牌从手牌升至场中央短暂停顿；己方角色持枪前探／举枪；枪口闪光和弹道飞向敌方；敌方后仰、命中亮光与数字；牌去弃牌或消耗堆 | 攻击不能表现为“把纸牌贴到敌人”；受击数字应出现在弹道到达后 |
| 布防牌 | 牌升至场中央；角色收身举臂；小型护甲／盾形反馈在己方模型周边出现；牌归堆 | 玩家能在不读数值的情况下看出布防 |
| 回合结束 | 所有未出的手牌依次飞入弃牌堆；明确显示敌人回合；敌方模型动作、射击／突进表现、我方受击及损失数字；新回合每张牌依次从抽牌堆进手牌槽 | 至少能辨认三个阶段，不能瞬间洗牌或瞬间结算 |

推荐普通动效时长：出牌约 650–900ms；单张弃牌约 260ms，错开约 70ms；敌方动作与命中约 700–950ms；抽牌单张约 260ms、错开约 80ms。依据手牌数延长总时长，绝不能在尾牌入场前解锁交互。减少动态效果设置下可缩短至 100–250ms，但仍保留阶段顺序。

## 工程接口

- `shared/character-stage-source.js` 构建轻量 Three.js 模型，暴露 `triggerCue('attack'|'defend'|'hit'|'idle')`，正确释放 WebGL 资源与 RAF。
- `shared/character-controller.js` 通过 `globalThis.characterStages.cue(side,cue)` 给两版调用；不要仅根据 action 类型推定所有牌都是攻击。
- 瓦 Demo 的主逻辑在 `ui-source.js`，表现层在 `combat-fx.js` / `combat-fx.css`；新 Demo 在 `new-demo/ui.js`、`new-demo/fx.js`、`new-demo/battle-fx.css`。可以新增共享工具，但不要更改游戏引擎。
- 所有命中／布防效果的目标位置由实时 DOM 读取，窗口缩放与手机视口仍可见。动画容器必须 `pointer-events:none`；页面切换、重新渲染后清理克隆节点和计时器。
- 禁止在普通玩家打开页面时调用 DeepSeek 或其他模型。

## 验收门槛

1. 两版从首页进入故事模式、开局、选择普通战斗，完整打出攻击／布防／结束回合，均无 JS 错误、卡死、重复结算或失去交互。
2. 敌我模型截图中肉眼可分；不同敌方关卡至少三种轮廓；动作不是静态图片平移。
3. 攻击阶段纸牌停在场中央或归堆，命中由角色动作与独立弹道表达。
4. 结束回合未打出的牌逐张入弃牌堆，下回合逐张抽牌；动画结束后手牌、弃牌、消耗堆与引擎状态一致。
5. 自动化测试、构建通过；本地桌面宽屏和窄屏浏览器试玩后再部署。验收不以 DeepSeek 自述“已测试”为依据。

## 分工记录

DeepSeek 负责共享角色模型／动作，以及两版战斗表现层的实现草稿和返修。主代理负责这份策划、核对 DeepSeek 输出、集成纠错、实际浏览器验收与上线。

## 本次实施与验收记录

- DeepSeek 交付两轮共享几何模型方案；本地截图证实仍像同款小人换色，因此未采用其最终美术方案。改采用其 Quaternius GLB 加载方案，并修正了 `SkeletonUtils` 导入、真实剪辑名称、动画恢复、镜头裁切、灯光与资源清理。素材来源和使用边界记录在 `shared/models/README.md`。
- DeepSeek 交付新 Demo 的攻击、布防、回合末弃牌／抽牌时间线和返修；本地发现第一次版本旧手牌残留、假卡抽入、牌面中途消失，主代理修成真实卡牌克隆和新手牌逐张入场。瓦 Demo 的回合动画与攻击特效使用了 DeepSeek 草稿，主代理集成并修正了触发时点。
- 本地桌面浏览器实测：两版均加载不同敌我 3D 模型；瓦 Demo 攻击后防线减少，未出手牌依次弃牌；新 Demo 攻击牌升到场中央后结算，回合末先弃牌、敌方行动、后逐张抽牌。`npm run build` 与 109 项自动化测试通过。
- 美术边界：当前属于第一轮可玩的卡通 3D 表现，七种敌人有三套基础模型并加上各自装备轮廓标记，仍不是七套独立雕刻模型。窄屏的视觉舒适度、各关卡敌人装饰物的逐一人工截图，以及动作的长期美术打磨留待后续专项验收。不能把它称为最终美术资产。
